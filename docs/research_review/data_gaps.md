# 現有資料與補充資料優先順序

查閱日期：2026-10-05。以下是資料盤點與研究建議，沒有下載新的大型 OD、重抓社群、修改 MySQL 或估計模型。MySQL 統計使用本機唯讀 SELECT；可重現的查詢、結果、檔案雜湊與擷取時間存於 [data_gaps.json](../../results/research_review/2026-10-05/data_gaps.json)。

**現在最需要的是補齊一般日基準、核對天氣時間與方法、接入假日表；不是再堆大量特徵。** 活動只有 26 個日期，其中真正施放 21 場。每場拆成許多站或小時，不會增加獨立活動樣本數。

## 2. 文字雲能提示的研究方向

已實際檢視 [Threads 圖](../../results/threads/web_sample_2026-07-15_2026-08-15/20260930T032540Z_14da527f/wordcloud.png)與 [PTT 圖](../../results/ptt/web_sample_2026-07-15_2026-08-15/20260930T034906Z_68ee14a6/wordcloud.png)，並核對同目錄的 summary、words 與 daily CSV。

- **Threads**：100 筆去重保留文章中，26 篇排除／待判定，74 篇納入；指定窗是 2026-07-15～08-15（32 日），15 日有樣本、17 日未知，實際最早樣本 07-18。「位置」6/74、「散場」「人擠」「碼頭」各 5/74、「人潮」4/74、「停車場」3/74。可提出「觀賞位置、離場時間、步行可達性與替代交通」假說。
- **PTT**：9 篇去重保留中 1 篇排除，8 篇納入；4 日有樣本、28 日未知，實際最早 07-24。「問卦」6/8、「施放」4/8、「人潮」3/8、「交通」「散場」各 2/8。圖中新聞／政治詞不少，可能受文章類型和轉貼新聞影響，不能把它當 8 位獨立旅客的意見。

詞頻是**含該詞的不同文章篇數**，不是詞出現次數；同一篇可以同時包含多個詞，不能相加當成不同人。上述是回顧性提示，尚未逐篇人工編碼證實。詞雲已排除「大稻埕／煙火／夏日節」等查詢詞，故最大字不是未篩選語料的絕對熱門詞。原圖的「人擠」也提示斷詞字典可改善。

若要把文字轉成變數，先人工抽查並標記「交通詢問／觀賞位置／擁擠抱怨／到場意圖／回顧分享／新聞轉貼」，保留多標籤與不確定類別，再由另一人覆核。分開活動前後、用來源 URL／新聞內容去重；不把抓取當下的累積互動數冒充事前互動量。只有 8 篇 PTT 不適合再細分很多比例後做顯著性檢定。社群沒抓到的日期是未知，不是零聲量。

## 3. 補資料清單

優先序 P0＝先修基礎；P1＝描述／預測第一版候選；P2＝確認研究目標後再投入。以下欄位名稱是建議，不代表已建表。

| 優先／狀態 | 資料與用途 | 欄位、粒度與 join key | 免費來源與歷史可取得性 | 注意事項 |
|---|---|---|---|---|
| P0／部分 | 一般日 OD：描述、預測 | 同站同來源時段起站人次；`service_date + source_hour + station`，比較日再映射 `event_date` | [北捷官方月索引](https://data.taipei/api/frontstage/tpeod/dataset/resource.download?rid=eb481f58-1238-4cff-8caa-fa7bb20cb4f4)列有 201907、202306、202507；免費。尚未下載驗證內容 | 不含活動日／異常日，補下載不是新增獨立活動 |
| P0／部分 | 氣溫、雨量、風、雲：描述；預測需當時預報 | `station_id + observed_at`；先經 `event_weather_station(event_date, station_id)` 限 primary，再按確認的時間區間對齊 | [CODiS](https://codis.cwa.gov.tw/StationData)可查歷史站資料；本專案已有 2017–2026 部分日期 | 雨量 T 是微量、& 是累積至後續，不當零；同時 join 2 站會放大人流列，雲量跨年測法須分開 |
| P0／缺少 | 國定假日、補班、連假：描述、預測 | `calendar_date, is_holiday, is_makeup_workday, holiday_name`；按實際曆日 join | [人事行政總處年曆](https://data.gov.tw/dataset/14718)列有民國 106～115 年 CSV，免費可追溯 | 政府辦公日曆不等同所有民眾工作日；保留修訂版本，週末不等同假日 |
| P1／部分 | 展演結束、舞台節目、交通／水門管制：描述、預測、步行模擬 | `event_date, planned/actual_end_at, restriction_id, mode, location, start_at, end_at, published_at`；時間區間重疊 join | [2026 官網](https://taipeisummer.travel.taipei/)、[2026 停車管制](https://pma.gov.taipei/News_Content.aspx?n=E43F2E5AE1223B3D&s=99037D911BF170D4)、[2023 公車改道附件](https://www.travel.taipei/file/34594/)；歷年公告可逐場人工追溯，非完整統一表 | 車輛禁行不等於行人水門關閉；活動結束不必等於煙火秒數加開始時間；實際臨時管制未必留存 |
| P1／部分 | 同日其他大型活動、疫情／停運干擾：描述、預測 | `other_event_id, venue, start/end_at, published_at, affected_station`；日期＋空間／受影響車站 | [臺北旅遊活動與消息 API](https://www.travel.taipei/open-api)及歷年官方公告免費；API 歷史完整性未確認，需逐場交叉查證 | 現有 `related_activities` 部分 NULL；只保留有來源的干擾，不能用全年粗旗標取代實際影響，也不要過度塞入參數 |
| P1／缺少 | 活動前天氣預報與警報版本：真正事前預測 | `issued_at, valid_from/to, forecast_area, rain_probability, temperature, warning_type`；`issued_at <= cutoff` 且有效時間覆蓋活動 | [CWA 短期過去資料 API](https://opendata.cwa.gov.tw/dist/opendata-history-swagger.html)、[歷史颱風資料庫](https://rdc28.cwa.gov.tw/TDB/public/typhoon_list/)；免費開放產品可先查，**未確認有完整 2017–2026 預報版本** | 觀測天氣不等於前一天可知；短期 API 不承諾多年歷史，查無歷史可先做回顧模型而非假稱真預測 |
| P2／部分 | Google／社群／公告聲量：預測增補 | `query, geo, published_at, collected_at, available_at, cutoff, source_id`；事件前固定窗後以 `event_date + query + geo` join | [Google FAQ](https://support.google.com/trends/answer/4365533?hl=zh-Hant)；[API Alpha](https://developers.google.com/search/apis/trends)仍需申請、近 5 年，不能涵蓋所有 2017 年資料；歷史社群完整性無保證 | 現有月指數先查來源與共同尺度；同月多場不能複製月值假裝事件差異；當月包含事後訊息。先驗證相較 OD＋日曆的增益 |
| P2／部分 | 步行路網、各出口／水門開放、觀賞區：流向模擬 | `node/edge_id, length_m, access_mode, entrance_id, valid_from/to`；空間 join 後建立 `event_date + route_id + station_id` | [官方出口座標](https://data.taipei/dataset/detail?id=cfa4778c-62c1-497b-b704-756231de348b)免費；[OSM 歷史查詢](https://wiki.openstreetmap.org/wiki/Overpass_API/Overpass_QL#Date)支援當時資料庫版本 | 地圖版本不保證當日可步行；目前手繪線、官方推薦步行時間皆非實際軌跡，需現場／管制核對 |
| P2／缺少 | 班距、列車餘裕容量、方向與月台到達：候車模擬 | `station_id + direction + train_id/arrival_at`；列車到離時刻、載客／下車／上車量、1–5 分鐘月台到達、進站管制 | [北捷班距](https://www.metro.taipei/cp.aspx?n=EAD981369A065968&s=0F3F913C344BA050)免費但屬現行概略；[TDX 歷史申請流程](https://tdx.transportdata.tw/about/service)需確認產品、日期、權限及費用；歷史實際餘裕容量未找到免費現成來源 | 平均班距不是活動加班車紀錄；列車總容量不是北門可上車容量；全站人次不是分方向月台到達量 |
| P2／缺少 | 實測候車／排隊標籤：模擬驗證 | 每方向每 1–5 分鐘 `queue_length, arrival_count, boarded_count, denied_boarding, wait_sample`；與班次時刻連接 | 未找到可免費回溯的 2017–2026 北門逐分鐘資料；可能需向營運單位申請或未來經同意現地人工計數 | 沒標籤只能做明示假設的情境敏感度；不得把逐時 OD 均分後當成實測分鐘序列 |

**候車模型的結構也要配合資料。** 若模擬列車候車，列車是間歇到達、批次載客且剩餘容量會變，不宜把「c 列車」直接代入 M/M/c 的 c 個持續服務櫃台。可先做分方向、有限容量、依班次發車的離散事件情境；沒有細時間資料時比較假設範圍，不報精準實測等待時間。這是建模建議，尚未校準或驗證。

## 4. 哪三個月份最值得先補

依目前的 D−7／14／21／28、排除事件表全部原訂日期規則推得：

| 補入月份 | 可改善的 held 活動 | 補齊後候選比較日數 |
|---|---|---|
| 201907 | 2019-08-03 | 4 |
| 202306 | 2023-07-05、07-12、07-19 | 4、3、2 |
| 202507 | 2025-08-06、08-20 | 4、2 |

這些是日期推算，不是承諾下載後一定完整。要再跑既有 OD 完整性檢查、排除假日與其他特殊活動。**2023-08-09、08-16 的四個候選日全部是事件表日期，補月份仍無法解決。** 可事先訂「更長回溯窗的同星期一般日」並檢驗趨勢變化，或保留無基準；不能為了湊樣本任意把颱風取消日當普通日。

如果當前目標只是描述人流與初步比較，先完成 P0，再選少量 P1 變數；固定／變動成本、車公里數留到「加班車成本或調度最佳化」研究目標確立後補。文字雲適合輔助選題，不是模型必要門檻。
