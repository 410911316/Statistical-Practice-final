# D−1 天氣資料查核與取得方式

查核日：2026-10-11。預測截止固定為活動前一天 **18:00（Asia/Taipei）**；預測目標為活動當天 18–23 時的人次。

## 結論

- 原本的 `data/original_data/大稻埕周圍雲量資料.csv` 是 **CWA CODiS 實測值**，不是前一天預報。既有查核雖然確認 1,008 筆觀測與官方資料相符，仍不能把活動當天天氣放入 D−1 預測。
- 本次另外取得 **NOAA GFS 當年實際運作的預報檔**：NCAR GDEX 提供點位數值，NOAA 公開 AWS 存檔時間證明同一個模式週期、預報時效的檔案在截止前已可取得。不是 ERA5、事後重分析或使用新版模式重做的 hindcast。
- 21 場活動中，**2021–2026 的 17 場**找到截止前的 AWS 公開物件紀錄；2017–2020 的 4 場保留 `unknown`。這不是宣稱早年沒有預報，而是本次未取得足以證明公開時間的紀錄。
- 可用欄位為 **2 公尺氣溫、10 公尺風速、全大氣總雲量**。沒有從本來源取得可核實的降雨機率，因此不填造降雨機率，也不以當天實測雨量替代。

已實際完成下載與轉換：**306 筆已驗證預報值**（17 場 × 6 小時 × 3 變數），另有 **72 筆明確缺值**，共 378 筆。已逐筆檢查初始化／公開／截止／有效時間順序、事件與小時對齊、單位及網格；並從原始端點重新計算全部 306 筆，確認內插和風速轉換一致。模擬「截止後才公開」「公開時間早於初始化」「缺少公開紀錄」皆被正確拒絕或保留缺值。

## 來源如何分工

| 來源 | 查到什麼 | 本次用途 |
|---|---|---|
| [CWA CODiS](https://codis.cwa.gov.tw/StationData) | 原專案的測站歷史觀測 | 留在事後描述、來源查核；不作 D−1 未來天氣 |
| [CWA 鄉鎮預報產品說明](https://www.cwa.gov.tw/Data/data_catalog/1-1-1.pdf) | 提供鄉鎮預報及發布時機 | 適合未來逐次保存預報；本次未找到涵蓋全部活動的公開歷史版本 API |
| [NCAR GDEX d084001](https://gdex.ucar.edu/datasets/d084001/) | 2015 年起 GFS 0.25° 操作型分析／預報存檔，00/06/12/18 UTC 模式週期 | 只取預報步、同一週期、同一地點的少量 CSV；不用分析步 f000 |
| [NOAA GFS 公開 AWS](https://registry.opendata.aws/noaa-gfs-bdp-pds/) | 可匿名讀取 GFS 檔案及公開物件 metadata | 逐檔驗證 `LastModified ≤ cutoff`，不把下載日期當發布日期 |

NCAR 資料集同時包含分析與預報，不能因資料集名稱含 forecast 就全部直接使用。本次使用活動前一天 **00 UTC** 初始化的 forecast steps `f033`、`f036`、`f039`，GRIB 週期與有效時間固定，不混入後來週期。NCAR 與 NOAA 的來源以模式、初始化時間、預報時效配對；本次不宣稱兩家存檔的整個 GRIB 位元組已做完全相同比對。

## 時間、地點與變數定義

1. **初始化不等於發布。** `forecast_issued_at` 因輸入介面沿用此名稱，實際保存 GFS 模式初始化時間；可用性判定只看 `published_at`。後者是本筆使用的所有端點 GRIB 之 AWS `LastModified` 最大值。物件時間是「最遲於此時已公開」的證據，不是氣象機關最早發布的精確時刻。
2. **固定取 D−1 00 UTC 週期。** 截止為 D−1 10 UTC，相隔 10 小時；程式仍逐檔驗證，而不是假設模式一定準時。若檔案缺漏或時間晚於截止，拒絕用新週期補值。
3. **同一預報場內做時間內插。** NCAR 保存的三小時預報點對應活動當天 17、20、23 時。18、19 時由 17／20 時線性內插，21、22 時由 20／23 時內插；20、23 時直接使用原點。兩端都來自截止前的同一個預報，因此不是用後來實測資料補值。
4. **數值代表整點瞬時預報。** 不是該小時平均、累積雨量或六小時平均。這是用來解釋該小時人流的環境特徵，不聲稱等同人流時段內的精確平均天氣。
5. **先內插風向量再算風速。** 使用 10 公尺 u、v 分量，分別內插後取 `sqrt(u²+v²)`；不是對風向角直接平均。氣溫由 K 減 273.15 轉為 °C；雲量單位為 %，只取 `Total_cloud_cover_entire_atmosphere` 瞬時欄位，排除 `_6_Hour_Average`。
6. **地理解析度有限。** 請求大稻埕附近 25.056°N、121.510°E，最近網格是 **25.000°N、121.500°E**。四個周邊捷運站共用此預報。0.25° 網格不能當成站口或河岸的微氣候實測；地形、雷雨和陣風誤差仍可能很大。

例如 2024/8/10 18 時的值，使用 2024/8/9 00 UTC 週期的 f033／f036。兩個來源檔案的 AWS 物件時間都必須早於 2024/8/9 10 UTC；再將預報有效時間 8/10 17 時與 20 時內插成 18 時。原始證據、網址、回應 SHA256、內插權重均保存在 JSON 中。

## 檔案與重現

- 蒐集程式：[`scripts/collect_d1_gfs.py`](../scripts/collect_d1_gfs.py)。最多 4 個並行活動下載，預設 3；只下載點位 CSV 與物件清單，不下載全球數百 MB 的 GRIB。
- 可提交的公開預報來源資料：[`docs/d1_weather_sources.json`](d1_weather_sources.json)。每筆包含 `event_date`、`hour`、`feature`、`value`、`published_at`、`forecast_issued_at`、`forecast_valid_at`、`availability_status` 與兩端來源證據。
- 原始 HTTP 回應與 SHA256 快取：`.local/d1_weather/`。同網址重跑使用快取；不更動 SQL，不讀取 `.env`。

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/collect_d1_gfs.py
```

模型載入時仍要再檢查「事件日期、有效小時、公開時間、截止時間」；不能只信任 `availability_status` 的文字。2017–2020 缺值也不能當成 0°C、零風速或晴天。若模型允許缺值，只能在各自訓練折學習補值，並保留缺值旗標；早年完全沒有天氣資料的訓練折，不能使用未來年份的天氣分布補值。

## 沒有採用的替代來源

- **Open-Meteo Historical Forecast API** 會接續多個預報週期，不能僅因日期相符就當成 D−1 截止時已知。[官方說明](https://open-meteo.com/en/docs/historical-forecast-api)
- **Previous Runs API 的 previous_day1** 以目標有效時間回推約 24 小時；目標 23 時所對應的前一日 23 時可能晚於本專案 18 時截止，不能直接套用固定 D−1 截止。[官方說明](https://open-meteo.com/en/docs/previous-runs-api)
- **Single Runs API** 能指定初始化時間，但初始化時間不是公開時間；其目前文件並將 2024 年起 IFS 存檔描述為 Cycle 49R1 hindcasts，因此本次不拿該早期版本充作當年已發布的真實預報。[官方說明](https://open-meteo.com/en/docs/single-runs-api)
- **前一日實測** 只有在觀測時段已結束、當時已發布且版本可追溯時，才能作為滯後特徵。既有 CSV 主要是活動當天觀測，不能平移日期冒充前一天已知資訊；這次未加入這類滯後值。

## 足不足以訓練

這批預報可供 17 場活動的事前天氣比較，但不是 17×6×4 個獨立活動樣本。同場、同時的四站天氣相同，逐時值也相關；應保持完整活動及年度的向前切分，不隨機打散資料列。首次加入天氣後仍須與同一外層活動的原模型比較，不能因加入更多變數就預設會改善尖峰。

即使天氣通過此查核，也不會自動使既有歷史人流基準或節目資訊通過 D−1 可得性查核；完整模型的事前可用性仍取決於所有輸入的證據。
